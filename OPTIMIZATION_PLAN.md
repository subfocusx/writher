# WritHer v1.1.0 — точки роста точности и скорости

> Назначение документа: зафиксировать возможности по повышению **качества распознавания (WER ↓)**
> и **скорости обработки (latency / RTF ↓)** для актуального GigaAM-пайплайна.
> Дата: по запросу пользователя. Основано на текущем коде (`asr_engine.py`, `recorder.py`,
> `main.py`, `audio_preprocess.py`, `punct_normalize.py`, `injector.py`, `models_registry.py`,
> `config.py`).
>
> ⚠️ Существующие `analysis_report.md` / `memory_analysis.md` и часть `analysis_v2.md`/`stability_audit.md`
> описывают **старую** версию (faster-whisper, Ollama, dual-pipeline, assistant.py), которой в коде
> больше нет. Здесь — только те точки, что релевантны текущему стеку: **GigaAM v3 E2E CTC (int8, ONNX)
> + Silero VAD (PyTorch) → воркер-транскрипция → regex-пунктуация → вставка через клипборд/Ctrl+V**.
>
> 🔄 **Ревизия 2026-09 (аудит безопасности):** каждая точка роста пересмотрена по фактическому коду
> с вердиктом «риск × влияние на качество». Цель — не только *что* менять, но **насколько это безопасно**
> для качества распознавания. Учтены: комплект моделей, реальный путь флагов препроцессинга,
> несущие sleep-ы в инжекторе, покрытие тестами. Вердикты см. в разделах 2/3 и сводке §5.

## 1. Карта текущего пайплайна (как есть)

```
Hotkey (AltGr)
  → Recorder.start()  (sounddevice, WASAPI, 16 кГц, callback-буфер + pre-roll 300 мс)
  → [toggle] Silero VAD (PyTorch, lazy) авто-стоп по тишине
  → Recorder.stop()   (drain 0.1 c, resample soxr/scipy/np.interp → 16 кГц)
  → _pipeline_queue   (один воркер _dictation_worker)
  → preprocess        (highpass / normalize / preemph — флаги из config)
  → GigaAMEngine.transcribe()  (CTC: 4-сек слайсы + 1-сек overlap + эвристическая сшивка)
  → punct_normalize   (regex-правила R1–R7)
  → inject (клипборд + Ctrl+V, _PASTE_WAIT = 2.0 c)
```

Процесс однопоточный по транскрипции: один `_dictation_worker`, внутри — блокирующий вызов
`recognize()`; inject с фиксированными sleep тоже в этом же потоке.

## 4. Метрики / валидация (как измерять)

- **Качество**: WER на референс-эталонной выборке русской речи (несколько диктовок с известным текстом), сравнение до/после каждой правки. Есть `scripts/test_gigaam.py` (бенчмарк fp32 vs int8) — расширить его до WER+RTF-харнесса.
- **Скорость**: latency (от стопа записи до инжекции) и RTF (время распознавания / длительность аудио). Замерять на типовой 5–15-сек диктовке.
- **Регрессии**: `tests/` (pytest) — весь существующий набор обязан оставаться зелёным после любых изменений. **Особенно релевантны:** `test_asr_overlap.py` (для п.2/п.13), `test_recorder_vad.py` (для п.7/п.8), `test_punct_normalize.py` (для п.3), `test_injector.py` (для п.11/п.15).

## 5. Рекомендуемый порядок работ (актуализирован с учётом безопасности)

1. **Быстрые и безопасные победы** (🟢, низкий риск): 
   - п.2 — **чunking >30 с → overlap** (подтверждённый баг потери слов, делать первым);
   - п.9 — прелоад VAD в фоновом warmup-потоке;
   - п.14 — `soxr` в requirements + spec;
   - п.10 — только тюнинг потоков onnxruntime (НЕ квантование);
   - п.6 — гигиена препроцессинга (сначала уточнить, какое pre-emphasis верно);
   - п.7 — AGC-нормализация входа VAD **под флагом `VAD_NORMALIZE` (дефолт OFF)** — реализовано (см. таблицу §2); включение → валидация на реальном микрофоне (§4).
2. **Средние** (🟡, под флагом/валидацией): п.8 (ONNX VAD — с проверкой эквивалентности), п.11 (неблокирующий inject, с учётом зоны стабильности), п.3 (пунктуация-модель с fallback, дефолт OFF), п.13 (overlap — в связке с п.1).
3. **Крупные / архитектурные** (🔴, только после бенчмарка CTC vs RNN-T и измерения WER): п.1 (дефолт RNN-T, требует доставки модели), п.12 (streaming partial decode), п.4 (LM/beam-rescoring), п.5 (custom words — неизвестный API), п.15 (снятие sleep-ов — только вместе с п.11).

## 6. Что НЕ трогать (зона стабильности)

- **`injector.py` как модуль** — механизм клипборд+Ctrl+V со hardware scan-кодами работоспособен и отлажен против багов «текст не появился»; менять только блокирующие ожидания (п.11/15), не сам подход.
- **Режим fallback** при ошибках распознавания (повтор транскрипции с преэмфазисом в `_dictation_worker`).
- **Recovery-путь** (сохранение промежуточного текста/аудио) — он спасает от потери данных, всегда должен оставаться срабатывающим.
- Все изменения точек роста — отдельными подтверждёнными шагами с замером WER/RTF до/после (п.4).
